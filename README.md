# temporal-easy

Onboarding guides for Temporal with Go:

- `docs/architecture/`: Temporal Architecture (8 chapters)
- `docs/workflows/`: Temporal Workflows (13 chapters)
- `docs/activities/`: Temporal Activities (10 chapters)
- `docs/client/`: Temporal Client (9 chapters)
- `docs/workers/`: Temporal Workers (12 chapters)
- `docs/error-handling/`: Temporal Error handling (9 chapters)
- `docs/namespaces/`: Temporal Namespaces (6 chapters)
- `docs/testing/`: Temporal Testing (9 chapters)
- `docs/observability/`: Temporal Observability (8 chapters)

The guides are plain Markdown. [VitePress](https://vitepress.dev) turns them into a static website with a left sidebar, search and a per-page table of contents.

## How the site is built

```
temporal-easy/
├── .github/workflows/
│   └── deploy.yml           # CI/CD: build and deploy to GitHub Pages on every push to main
├── package.json             # scripts + vitepress dependency
├── .npmrc                   # project registry (public npm, not Artifactory)
├── pnpm-workspace.yaml      # pnpm settings (allows esbuild's install script)
├── topics/                  # one topic file per guide, read by /temporal-doc Claude command
│   ├── .template.md           # empty topic file to copy
│   ├── workflows.md
│   └── activities.md
├── .claude/                 # /temporal-doc command + temporal-guide-writing and temporal-vitepress skills
└── docs/                    # VitePress source root
    ├── .vitepress/
    │   ├── config.mts         # site config; builds nav + sidebar from the folders
    │   └── theme/             # default theme + JetBrains Mono, wider content, GuideCards.vue
    ├── index.md               # home page: one card per guide, generated
    ├── architecture/          # same layout as workflows/
    ├── client/                # same layout as workflows/
    ├── workers/               # same layout as workflows/
    ├── error-handling/        # same layout as workflows/
    ├── namespaces/            # same layout as workflows/
    ├── testing/               # same layout as workflows/
    ├── observability/         # same layout as workflows/
    ├── workflows/
    │   ├── docs/*.md          # chapters (README.md is the overview)
    │   └── img/*.svg          # diagrams
    └── activities/
        ├── docs/*.md
        └── img/*.svg
```

VitePress builds every `.md` file into a page at the same path, under the `/temporal-easy/` base: `docs/workflows/docs/05-timers-selectors-concurrency.md` is served at `/temporal-easy/workflows/docs/05-timers-selectors-concurrency`. This `README.md` lives outside `docs/`, so it is not part of the site.

```sh
pnpm install        # once
pnpm docs:dev       # live-reload server on http://localhost:5173/temporal-easy/
pnpm docs:build     # static site in docs/.vitepress/dist/
pnpm docs:preview   # serve the built site on http://localhost:4173/temporal-easy/
```

The project uses pnpm (CI pins the same version in `.github/workflows/deploy.yml`; update it there when you upgrade pnpm locally). The local `.npmrc` points it at the public npm registry, which overrides the global Artifactory registry for this folder only.

## Deployment

The site is published on GitHub Pages: <https://quentinliso.github.io/temporal-easy/>.

**How it deploys.** Every push to `main` runs `.github/workflows/deploy.yml`:

1. `build` job: installs pnpm and Node 24, runs `pnpm install --frozen-lockfile` and `pnpm docs:build`, and uploads `docs/.vitepress/dist/` as the Pages artifact. A failed build (dead link, Vue syntax error, outdated lockfile) stops here and nothing is deployed.
2. `deploy` job: publishes the artifact to GitHub Pages. The run page shows the live URL.

To redeploy without a new commit: Actions tab → "Deploy site" → "Run workflow".

**Before pushing:**

1. `pnpm docs:build` must end with "build complete".
2. `pnpm docs:preview`, then open <http://localhost:4173/temporal-easy/> and check the pages you changed.

**After pushing:**

1. In the Actions tab, both jobs of the "Deploy site" run are green (about a minute).
2. On the live site, open a guide card, a chapter and a diagram, try the search, and reload a deep link (for example `/temporal-easy/testing/docs/07-replay-testing`) to check it doesn't 404.

**When a run fails:** the site keeps the last good version. Open the failed run's log, fix the problem locally (`pnpm docs:build` reproduces build errors), and push again.

**One-time setup** (in the GitHub UI):

- Settings → Pages → Build and deployment → Source: **GitHub Actions**.
- `base` in `docs/.vitepress/config.mts` must match the repository name (`/temporal-easy/`). If you fork or rename the repository, change it, or the pages load without styles.
- GitHub Pages on a private repository needs a paid GitHub plan.

## Topic files

Each guide is generated by Claude Code from a topic file in `topics/`. A topic file lists what to document and which pages to read, in three sections:

```markdown
# Temporal feature
Workflows

# Temporal Encyclopedia
https://docs.temporal.io/workflows
https://docs.temporal.io/workflow-execution

# Temporal Go SDK
https://docs.temporal.io/develop/go/workflows/basics
https://docs.temporal.io/develop/go/workflows/timers
```

- `# Temporal feature`: the feature to document. It names the guide folder `docs/<feature>/`.
- `# Temporal Encyclopedia`: the Encyclopedia pages to read, one URL per line.
- `# Temporal Go SDK`: the Go SDK pages to read, one URL per line.

`/temporal-doc topics/<feature>.md` reads the topic file, then:

1. writes the guide into `docs/<feature>/` with the `temporal-guide-writing` skill, reading the Encyclopedia and Go SDK pages side by side;
2. publishes it on the site and checks the build with the `temporal-vitepress` skill;
3. reports the chapters written, the diagrams, the discrepancies found between the docs and the SDK, and the build result.

If the argument is missing or the file does not exist, the command stops and asks which topic file to use.

To document a new feature, copy `topics/.template.md` to `topics/<feature>.md`, fill in the three sections and run the command. To regenerate a guide after the Temporal docs change, edit its topic file and run the command again.

## Contributing

- **New chapter:** add `NN-short-slug.md` to `docs/<guide>/docs/` and start it with a `# NN · Title` heading. The sidebar picks it up automatically and uses the heading text up to the first `:` as the label.
- **New Temporal feature:**
  - Create `docs/<feature>/docs/README.md` (the overview), the numbered chapters and `docs/<feature>/img/`.
  - The feature then appears automatically as its own sidebar section and as a card on the home page.
  - To control its position, add it to `guideOrder` in `docs/.vitepress/config.mts`. Unlisted features are added alphabetically.
- **Diagrams:** put SVGs in the guide's `img/` folder and reference them with `![alt](../img/name.svg)`.
- **Links:** use relative links to the `.md` file, such as `[Versioning](./11-versioning.md)` or `[Activities](../../activities/docs/README.md)`.
- **Code samples:**
  - Use fenced blocks with a language (`` ```go ``).
  - Use production-like names such as `ProcessInvoiceWorkflow`, not `YourWorkflow`.
- **Vue syntax:** VitePress compiles Markdown through Vue. Put `{{ }}` and anything that looks like an HTML tag (`<T>`, `<nil>`) in prose inside backticks.
- **Before pushing:** run `pnpm docs:build`. It fails on dead internal links, and so does the deploy pipeline. Links to the local Temporal UI (`http://localhost:8233`) are allowed. See [Deployment](#deployment).
- **Generating a guide with Claude Code:** write `topics/<feature>.md` from `topics/.template.md`, then run `/temporal-doc topics/<feature>.md`. See [Topic files](#topic-files).
